# Local Roamer worker

Run `npm run worker` from the project directory with the Grok desktop application signed in. The pinned `grok-bot-cli` reads that application's local session; no Grok credential is sent to Vercel or Supabase.

The worker needs `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `ROAMER_USER_ID`, `TAVILY_API_KEY`, and `APIFY_TOKEN` in its process environment. The npm script loads the two local environment files. Do not put service keys in `NEXT_PUBLIC_*` variables.

One worker owns the `laptop` process heartbeat. A local PID lock prevents duplicate workers. Each trip is bound to the conversation bot and optional research bot registered in its owner's workspace. Missing or unregistered bindings are errors; they never fall back to another traveller's bot. Each bot has one active task, an independent transcript cursor and a `laptop:<bot-id>` heartbeat. The personal conversation bot is polled continuously for native voice; other bots are polled during work and for ten minutes afterwards to catch delayed replies. At most eight jobs run together, including three provider searches; the CLI has four concurrent calls and Apify has two actors. Each actor has a $0.25 charge ceiling and 150-second timeout. Raw provider responses remain in ignored `.roamer/evidence/` files; only dated, normalized quotes and source references enter the trip state.

Grok replies with the tagged JSON contract in `bridge.ts`. Assistant messages are the only transcript entries ingested. Stable event IDs include the bot ID, because transcript entry IDs can repeat across bots. Web replies must echo their `commandId`; unsolicited native voice updates omit it and are accepted only from that trip's bound conversation bot. Browser jobs may update only their requested candidate's quote or transport evidence and a short message. Criteria revisions protect the current trip from old replies. Providers use dependency fingerprints so changing a preference does not discard an unaffected flight search.

The worker records message delivery as uncertain before sending. A failed or interrupted send is never automatically repeated. A late reply can reconcile its owned, persisted command after the active waiter has timed out; it must still match the bot, trip, command and current revision. A current browser scope is additionally required for late browser evidence. Expired searches become retryable errors; uncertain conversation delivery has no automatic Retry action. The worker renews active leases every 15 seconds.

Startup and queue outages use an exponential reconnect delay capped at ten seconds. They do not terminate the scheduler or discard its cursor and active jobs. Failed transcript reads retry once; repeated failures change the heartbeat to `degraded`. Grok event commits atomically queue destination expansion, so the transcript poll does not wait for all candidate and provider queue writes.

Failed structured flight/stay searches request a scoped computer check from the trip's research bot (or its own conversation bot when no separate research bot is configured). Browser prices are accepted only for a sent, persisted requested job, with matching destination, kind, command ID, dates, party and currency. A queued browser job is retired if its relevant trip details or selected stay change. Successful fallback keeps the scraper failure in history and removes its active retry state. Transport checks can start as soon as a current stay arrives while other searches continue. A price that cannot be checked remains missing. Failed actor receipts are kept in `.roamer/evidence/`; actor launches are never blindly repeated after uncertain network delivery.

Apply workspace migration 006 and seed the owner-controlled bot registry before starting this worker. Migration 005 preserves the old claim function; 006 replaces the parallel claim function with trip bindings. The isolated worker uses `.roamer/worker-v2.lock` and excludes legacy bots from polling and sending. During the one-time cutover, the old worker may finish an already leased task only after migration 007 disables its claims and the parallel scheduler excludes legacy work. Stop that old process when it drains; the versioned lock does not authorize two isolated workers. Existing bots share an account computer, files and logins even though each bot has its own screen; these workspaces isolate conversation/task routing, not cloud-computer accounts.

Native voice remains in the Grok app. A structured ordinary chat reply is required for the web companion to update; speech alone cannot update it. Actual spoken voice synchronization must be checked in a real voice call. The browser verification task asks Grok to visit sources and returns linked evidence, but cannot independently attest to the bot's native computer trace through the bridge.

Provider and transcript boundary tests: `npx vitest run src/worker/worker.test.ts`. These tests do not consume provider credits. Live search tests must use separate, explicitly identified trips.
